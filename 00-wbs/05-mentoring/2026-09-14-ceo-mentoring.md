## 1. 좋은 평가 — 유지할 것

| 슬라이드 | 내용 | 코멘트 |
| --- | --- | --- |
| ERD (9-10p) | 재고를 중앙에 배치하고, 생산(공급망)-재고-판매 사이 흐름으로 설명 | 가장 인상 깊었다는 평 — 발표 전체 스토리텔링 축으로 확대할 가치 있음 |
| 시스템 아키텍처(6p) 내 데이터 흐름 | nqnq.db → Blob → Data Factory → Databricks | 괜찮다는 평, 그대로 유지 |
| 아키텍처 구조 | 초반 PaaS(Data Factory·Databricks) → 후반 SaaS(Dataverse·Power Platform) | 흥미롭다, 결과물 기대된다는 평 |

## 2. 지적사항 — 수정 필요

| 슬라이드 | 문제 | 개선 방향 |
| --- | --- | --- |
| 전체 흐름 | "비전공자를 배려하지 않는다", 두서없다는 총평 | 기술명(서비스 로고) 나열 대신 왜/어떻게에 대한 내러티브를 먼저 배치 |
| ERD 상세 (9-10p) | 14개 엔티티 PK/FK를 전부 노출 | 재고 중심 핵심 4~5개 테이블만 남긴 축소판을 메인에, 전체 ERD는 백업 슬라이드로 이동 |
| 데이터 생성 현황 (8p) | 94~109% 정확도 등 숫자만 있고 "왜/무엇을 증명하는지" 근거 연결 없음 | 11p 실험계획(정확도 라이브 검증·risk_score 트리거 검증)과 통합해 "이 데이터로 이걸 검증한다" 흐름으로 재배치 |
| Databricks 5단계 (7p) | `01_ingest`, `auto_decidable` 등 코드·변수명이 타이틀 레벨 노출 | 사람이 읽는 언어를 1차 표현으로, 코드명은 서브텍스트로 축소 |

## 3. 확장 제안 — 안건화 대상

- Dataverse 채택 근거를 "C# 개발 경험 때문"보다 **Power BI·Teams·SharePoint 연동 등 Power Platform 생태계 시너지**로 재구성해보라는 제안
- 지금까지 만든 **백엔드(C# Web API) + 프론트엔드(ASP.NET Core MVC 대시보드) + 웹서버 전체를 앱(Power App 등)으로 전환 가능한지** — 최민이 확인 중, 결과 보고 후 확정
- SharePoint·Power Platform 등 추가 MS 자원 활용 방안을 구체화해보라는 요청

## 4. 대표님이 질문/확인한 것 (참고용)

- 시스템 아키텍처·머신러닝에 대해 상세 질문 다수 — ML은 담당자(임현제) 설계 이전 단계라 초기안이며 추후 구체화 예정이라고 답변함
- Dataverse를 실제로 쓰는 팀은 처음 본다며 흥미로워함, SAP 옆에 애드온으로 붙는 발상을 긍정적으로 평가

## 5. 부수 소식 (참고)

- Dataverse/Power Automate 라이선스: 대표님이 책임자에게 요청해 **팀당 2명으로 완화 승인을 시도** 중 (미확정) — 확정되면 [[5-dataverse-guide]] 3-3절에 반영
