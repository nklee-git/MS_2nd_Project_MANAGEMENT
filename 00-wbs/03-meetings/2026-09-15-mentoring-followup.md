## 5. 안건 5 — Data Factory 유지 여부 재검토 (신규, 대표님 코멘트 계기)

**배경**: 대표님이 "Data Factory를 굳이 넣은 이유가 뭔가, Azure Functions로도 될 것 같다"는 코멘트를 줌. 팀 내부에서 바로 논의:
- **임현제**: 대표님 의견에 동의 — "현업에서 잘 안 쓰는 툴은 도태된다, 남들이 더 많이 쓰는 서비스를 쓰는 게 좋다"는 입장, Functions 전환에 무게
- **최민**: Data Factory 유지 희망 — 채용공고에 자주 언급되는 스택이라 이력서 한 줄로 욕심남. "다른 팀원이 필요없다고 생각하면 어쩔 수 없다"고 한발 물러섬
- **나경 잠정 결정**: 최민이 일단 Data Factory 기반으로 오케스트레이션을 시도 → 안 되거나 팀 합의가 바뀌면 Functions로 갈아타는 선택지를 남겨둠

- [ ] 위 잠정 결정 그대로 확정할지 재논의
- [ ] Functions 전환 시 아키텍처 초안 공유: 실시간 데이터 생성모듈(소규모) → Azure Functions → DB 적재 / Functions → Event Hub → Stream Analytics → Azure PostgreSQL(비용 문제 있음, [[23-cost-plan]] 검토 필요)
- [ ] DB 마이그레이션 방침 확인: 현재 Azure SQLite에 적재 중 → 데이터 규모 커지면 PostgreSQL로 마이그레이션 범위 확장(시점 미정)

**워크플로우 재배정 (데이터 적재 우선)** — 박형준은 customer·factory 테이블만 적재하면 끝나는 상태. 이후 순서:
1. 데이터 적재 이어받아 완료 — 담당: 나경 (형준 인수인계)
2. 배포 — 담당: 최민
3. 데이터 적재 끝나면 Databricks 후속작업 — 담당: 임현제

- [ ] 이 순서·담당자 이견 없는지 확인
