**최민 반박 — 개발 프로세스 원칙 제시**
- 데이터 생성→적재 파이프라인을 먼저 구축한 뒤 RAG/LLM을 진행하는 게 경험상 맞다는 입장. Dataverse 적재는 애초에 나경이 "Data Factory보다 Dataverse를 쓰고 싶다"고 사전 지시한 것을 따른 것뿐이라고 정정 요구 — "아키텍처상 팩토리 적재"와 "7개 테이블 Dataverse 적재"가 서로 모순된다고 지적
- 실무 경험상 표준 개발순서(요구사항분석→설계→구현→테스트, 애자일 모델)를 언급하며, 이 프로젝트엔 "데이터생성→데이터적재→RAG/LLM학습→백엔드→프론트" 순서를 제안
- 테크리더가 없는 상태로 진행 중이라면 팀장(나경)이 기술스택을 명확히 정해야 한다고 요청 — "어떤 툴을 쓸지 계속 바뀌면 금요일 같은 일이 또 생긴다"고 경고

**이나경 정정 — 아키텍처 문서 재확인 후 파이프라인 순서 확정**
- [[21-system-model]] 6절 기준 실제 순서를 재확인: "로컬 데이터 → Data Factory 오케스트레이션 → Databricks ML 처리 → 예측 결과만 Dataverse 적재". Dataverse는 원본 테이블을 정규화해 옮기는 저장소가 아니라, Factory·Databricks를 거친 발주추천(`ReorderRecommendation`) 결과만 받는 단일 저장소로 설계돼 있음을 확인
- 사전에 "팩토리보다 Dataverse부터 쓰자"고 지시한 것 자체가 문서 순서와 어긋난 지시였음을 인정, 최민은 지시를 그대로 따른 것뿐이라 책임이 없다고 재확인하며 재차 사과
- 현재 Dataverse에 이미 올라간 14개(+예정 7개) 테이블이 원래 소스단(로컬 db) 또는 Factory 처리과정에 있어야 할 데이터인지 재판단 필요 → 일요일 미팅 안건 3가지 제안: (1) 6번 아키텍처 기준 재확인 (2) 현재 Dataverse 테이블 중 유지/이관 대상 결정 (3) 이후 기술스택 고정 원칙
- **전체 파이프라인 순서를 7단계로 명문화**:
  1. 원시데이터 적재(Blob Storage) — `nqnq.db`(500MB, 14개 테이블)를 Azure Blob Storage/ADLS Gen2에 업로드 = 다이어그램상 "src" 위치, Dataverse는 원시데이터 정착지가 아님
  2. Data Factory 파이프라인 구성 — Blob을 소스로 Databricks 노트북을 트리거하는 오케스트레이션만 담당(500MB 자체를 옮기고 변환하는 역할이 아니라 스케줄/트리거 역할)
  3. Databricks 처리 — 소형 클러스터(15~30분 자동종료 필수, [[23-cost-plan]] 참고)로 Blob 마운트, 전처리·피처엔지니어링(판매속도·재고소진일·계절계수)·수요예측 모델·`risk_score` 산출까지 전부 처리(500MB는 소형 클러스터로 충분)
  4. Databricks→Dataverse 직접 적재 — 노트북 마지막 단계에서 Dataverse Web API를 호출해 `ReorderRecommendation` 테이블에 결과만 upsert([[5-dataverse-guide]] 5절 — 임현제 담당으로 이미 명시됨), 결과는 SKU 단위 추천이라 몇십~몇백 row 수준
  5. Dataverse 신규 행 → Power Automate → Teams 승인카드
  6. 승인/반려 → Power Automate가 Dataverse status 업데이트
  7. 대시보드가 Dataverse Web API로 조회해서 화면 표시

**테크리드 공백 이슈**
- 이나경: 최민을 테크리드로 여기고 진행했으나 방향성 업데이트가 안 됐음을 인정 — 본인이 내릴 수 있는 결정 수준은 "제 클로드를 믿는 수준"이라고 자평, 최민에게 설계방향 오류나 생각하는 방향성을 정리해 알려달라고 요청
- 최민 응답: ① 대시보드가 Dataverse만 참조하고 Factory단 데이터는 RAG/LLM 적재 전용인 경우 비용 측면 검토 필요, ② 대시보드가 Factory(Azure DB)와 Dataverse를 모두 참조하는 방식이면 그 기준점도 명확히 정해야 한다고 지적
- 데이터 기술 검토 항목 2가지 제기: ① 실시간 데이터생성→엑셀 생성→Azure DB 적재(기존 모듈 고도화) ② 이미 만들어진 더미데이터를 백엔드에서 날짜별 ASC 조건으로 단위별 순차조회가 가능한지 — 현직 개발자에게 문의 중, 답변 오면 공유 예정

**일요일 회의 조율**
- 이나경이 최민에게 감사 인사 후 일요일 회의 가능 시간 문의 → 최민은 다른 사람들 시간에 맞추겠다고 회신 → 임현제·박형준 확인되면 일정 확정 예정

**한줄리뷰**: Dataverse를 파이프라인 앞단(원본 적재소)으로 잘못 쓰도록 이나경이 사전 지시했던 것이 뒤늦게 드러나 최민과 마찰이 있었지만, [[21-system-model]] 재확인으로 "Blob→Factory→Databricks→Dataverse(결과만)" 7단계 파이프라인을 명문화하며 정리됨 — 이후 작업의 기준선이 된 문서화. 테크리드 공백(최민이 사실상 역할을 하고 있었지만 공식화·소통이 안 됐던 문제)도 이 사건으로 수면 위로 드러남.
